# MAP_PROMT.md — CoreLink.Maps → CoreLink.Rx

**Проект:** CoreLink.Foundation  
**Дата фиксации:** 10.11.2026  
**Статус:** согласованная концепция, не считать её реализованной до изменения исходников и проверки.  
**Связанные документы:** [PROMT.md](PROMT.md), [RX_CONTRACTS.md](RX_CONTRACTS.md), [CLIENT_CONTRACTS.md](CLIENT_CONTRACTS.md).

## 1. Назначение и границы

`CoreLink.Maps` описывает конкретную сборку устройства и подготавливает **две согласованные проекции из одного определения регистров**:

- бинарную `CoreMap` v2 для Core (адрес, тип, порядок и техническая конфигурация обмена);
- managed-метаданные для `CoreLink.Rx` (техническое имя, единицы UA/EU, позиция значения, идентификатор системы единиц, интервал Rx).

`CoreLink.Client` загружает карту и передаёт нужную проекцию соответствующему слою. `CoreLink.Rx` не читает физические адреса и не открывает карту самостоятельно. `Maps` не выполняет TCP, polling и преобразование поступивших значений.

**Бинарный формат Core v2, `ICore`, Transport и схема polling не меняются ради managed-карты.** Фактический публичный API передачи managed-проекции ещё не утверждён: текущий `IMapProvider.TryLoad(mapId, out CoreMap?)` выдаёт только бинарную карту.

## 2. Единственный источник параметров

Основное описание технологических параметров — существующий `RegisterMap`, массив `PhysicalRegister[]`. Каждая запись задаёт техническое имя `Name`, адрес `Address`, `RegisterType` и, **если нужны единицы**, описание `Units`.

Единицы задаются **в той же записи** регистра. От отдельной `UnitsMap` и сопоставления двух карт по строкам отказались. Ни рефлексия, ни runtime-поиск имён для связывания единиц не нужны.

`ValueId == index` — индекс позиции записи в `RegisterMap` равен индексу декодированного значения в snapshot и позиции managed-описания Rx. Порядок менять без согласования нельзя. Одна величина `Float32` из двух Modbus-регистров — **один** `ValueId`, а не два.

Изменение физического адреса, состава и порядка регистров между сборками допустимо. `mapId` и выбор конкретных конфигураций должны опираться на явный контракт; **в существующем `MapProvider` параметр `mapId` пока не используется**.

## 3. Типизированные единицы

- `UA` — отдельный enum американских единиц.
- `EU` — отдельный enum метрических единиц.
- `Units` — структура, объединяющая выбранную единицу `UA` и выбранную единицу `EU` для **конкретного** параметра.
- Список допустимых единиц заполняется явно. Не использовать строки, рефлексию и автоматическое определение физической совместимости.
- У разных параметров допускаются разные единицы внутри одной системы (например, `EU.Bar`, `EU.MPa`, `EU.Atm`).
- Если `Units` не задана, обозначения единиц пустые. Значение enum `0` тоже означает **отсутствие единицы**, не ошибку. Исключить трактовку нулевого enum как реальной физической единицы.
- Повторение единиц в записях регистров допустимо и предпочтительнее дополнительного механизма группировки.
- Добавление новых систем в будущем — отдельное явное расширение описания, без преждевременного универсального framework.

**Иллюстративный синтаксис (не утверждённая сигнатура):**

```csharp
new("Pressure_1", 7, RegisterType.Float, new Units(UA.PSI, EU.Bar))
new("Pressure_2", 9, RegisterType.Float, new Units(UA.PSI, EU.MPa))
```

Это пример формы записи, не разрешение автоматически менять текущие публичные типы или порядок аргументов.

## 4. Выбор системы измерения PLC

Систему единиц задаёт **технический регистр** с точным именем `Measurme` (написание намеренное; указать его в комментарии карты). Сравнение строго по `StringComparison.Ordinal`; без алиасов, нормализации регистра или исправления опечаток.

Соответствие фактического значения:

| Measurme | Система |
| --- | --- |
| `1` | `UA` — американская |
| `2` | `EU` — метрическая |

- Если `Measurme` **вообще отсутствует в RegisterMap**, использовать `UA` (`1`) по умолчанию. Это штатная конфигурация, без ошибки и лога.
- Если запись `Measurme` есть, её **ValueId определяется позицией в текущем RegisterMap**, физический адрес не фиксируется. Нельзя подставлять систему `1` вместо некорректного или недоступного значения существующего `Measurme`.
- Если значение присутствующего `Measurme` некорректно, нецелое, неопределённое или не поддерживается, единицы обозначать `—`; зарегистрировать диагностическое событие ошибки выбора Unit. Числовые значения не пересчитывать.
- Если `Measurme` есть, но ещё **не было успешного snapshot**, измерения не публиковать; нет подтверждённой системы единиц. Фиксировать проблему выбора Unit в диагностике, не выдавая `0` из неинициализированного массива за чтение PLC.
- Если после успешного чтения связь потеряна, **сохранить последнее значение и последнее обозначение единицы**, пометить данные как устаревшие (stale). Не заменять единицы прочерками лишь из-за disconnect.
- При возвращении корректного значения единицы определяются по свежему snapshot; фиксировать восстановление после ошибки Unit.
- Повторяющуюся причину ошибки не записывать в лог каждый цикл (сейчас Rx-интервал 500 мс). При изменении причины ошибку диагностировать отдельно.

**Различать:** отсутствие описания единицы (`0` / не задано) — нормальное пустое обозначение; ошибка существующего `Measurme` — прочерк `—` и диагностическое событие. Отсутствие `Measurme` — нормальный default `UA`.

## 5. Обработка и локализация

PLC отдаёт числовые данные в выбранной на PLC системе; Core декодирует регистры в `float[]`. Rx выбирает **только техническое обозначение единицы** для выбранной системы. Никаких пересчётов между UA/EU, масштабирования или проверки физической совместимости единиц.

**Локализация целиком принадлежит Avalonia**, CoreLink не переводит интерфейс. `Name` — стабильный технический идентификатор параметра; заголовки, кнопки, статусы и подписи переводит Avalonia. При смене языка `psi` остаётся `psi`, а числовое значение не меняется. Переключение языка не запускает polling, не перезапускает Client/Rx и не меняет `Measurme`.

## 6. Интеграция Rx

Из общей исходной карты Maps подготавливает в порядке `RegisterMap` данные, необходимые уже существующему `CoreLinkRx`: определения значений, признак/позицию `Measurme`, интервал `RxIntervalMs` (сейчас 500 мс). Длина списка определений соответствует `CoreMap.BufferLength`.

Текущий `CoreLinkRx` принимает обязательный `int unitSystemValueId`; для режима **без Measurme** его контракт потребуется согласованно адаптировать. Не выдумывать фиктивный индекс и не менять формат бинарной CoreMap. `RxValueDefinition` в текущем коде хранит `IReadOnlyDictionary<int,string>`; переход к типизированным UA/EU — предмет отдельного минимального изменения карты и подготовки Rx-метаданных, а не подтверждённая текущая реализация.

Snapshot поступает Rx **через Client**, не напрямую из Core/Transport. Последовательный цикл Rx и публикация только изменений остаются по [RX_CONTRACTS.md](RX_CONTRACTS.md).

## 7. Правила реализации и ошибки

1. До изменения кода изучить актуальные файлы `PhysicalRegister`, `RegisterMap`, `CoreMapEncoder`, `MapProvider`, `IMapProvider`, `RxValueDefinition` и `CoreLinkRx`; согласовать затрагиваемый API.
2. Код — **в чате, один полный файл за шаг** для review разработчиком. Изменения на GitHub вносить только по отдельному указанию. Минимальный diff, без параллельного рефакторинга.
3. Технических долгов не оставлять. Если согласованное отложенное действие остаётся — `TODO` с причиной и условием выполнения; временный обходной путь — `FIXME` с условием удаления.
4. Ошибки не пробрасывать во внешний UI или вышестоящие слои как штатную модель отказа. Сохранять первопричинные статусы и доступную диагностику; запрещены пустые `catch`, фиктивный успех и маскировка под `Disconnected`.
5. Централизованное логирование подключить отдельным этапом; до этого предусмотреть диагностические точки с `TODO` и указанием события. `TODO` не заменяет текущую обработку ошибки.
6. Не менять Core v2, ICore, Transport, reconnect и polling в рамках задачи карты без дополнительного решения.
7. После каждого файла: build → целевая проверка → human review → commit. Не заявлять о проверках без фактического выполнения.

## 8. Реальное состояние на дату контракта

- `RegisterMap` содержит `Status`, `Cutoff`, `Speed`, `Pressure_1`…`Pressure_5`, **без `Measurme`**; это допустимый случай default UA.
- `PhysicalRegister` сейчас содержит лишь `Name`, `Address`, `Type`; структура `Units` и enum `UA`/`EU` ещё не введены.
- `CoreMapEncoder` производит бинарную карту v2 и не хранит имена/единицы.
- `MapProvider.TryLoad` сейчас отдаёт только `CoreMap`; managed Rx-проекция ещё не сформирована.
- `RxValueDefinition` и `CoreLinkRx` уже существуют; новая схема выбора системы и типизация единиц **ещё не интегрированы**.

Реализация выполняется после review и отдельного разрешения разработчика согласно [PROMT.md](PROMT.md).
