# CoreLink.Foundation — архитектурный промт v9

**Репозиторий:** https://github.com/Bodden007/CoreLink.Foundation  
**Актуализировано:** 10.11.2026  
**Стек:** C# / .NET 10 / NModbus 3.0.83; NativeAOT — требование, не подтверждённая публикация всего решения.  
**Источники подробностей:** [CLIENT_CONTRACTS.md](CLIENT_CONTRACTS.md), [RX_CONTRACTS.md](RX_CONTRACTS.md), [MAP_PROMT.md](MAP_PROMT.md).

## 1. Правила инженерной работы

- Приоритеты: **надёжность → предсказуемость → сопровождаемость → простота → NativeAOT → производительность**.
- **Изучать актуальные исходники перед изменением.** Документы фиксируют контракт и проверенное состояние, но не подменяют ревью кода.
- Не менять утверждённые границы компонентов, имена, сигнатуры и структуру без явной необходимости и согласования. Минимальный diff; не добавлять инфраструктуру «на будущее».
- Без запроса не генерировать код. По умолчанию показывать **один полный файл за шаг**; если разработчик прямо просит все файлы разом, выдавать все полные файлы в чате. Не предлагать архив вместо явно затребованного текста.
- Изменять GitHub, создавать коммиты/PR, отправлять изменения только по **явному указанию разработчика**. При изменениях в GitHub сообщать пути и коммиты; о необходимости локального `git pull` предупреждать.
- После изменений: сборка → целевой тест → оценка отказов → review → commit. Компиляция не равна проверке runtime и NativeAOT.
- Не оставлять технические долги незаметно: `TODO` — действие и причина; `FIXME` — известный дефект и условие удаления. Не называть планируемое реализованным.
- **NO EXCEPTION PROPAGATION на внешних границах** Client/CoreLink/Rx: возвращать согласованные статусы, сохранять диагностическую причину, не маскировать внутреннюю ошибку под `Disconnected`, `NoData` или успех. Исключения внутри компонентов локализовать; неисправного Rx-подписчика изолировать. Наличие `throw` в существующих внутренних конструкторах требует адресного аудита, а не необоснованного утверждения о полном соблюдении правила.

## 2. Утверждённая архитектура

```text
Avalonia / приложение
         |
         v
   CoreLink.Client <----> CoreLink.Rx (hot Values / Statuses)
         |
        ICore
         |
 CoreLink.Adapter.CSharp
         |
   CoreLink.Core
         |
 CoreLink.Transport
         |
     Modbus TCP
         |
        PLC
```

- `CoreLink.Contracts`: типы, `ICore`, карта v2, `RxMapConfiguration`, `IMapProvider`.
- `CoreLink.Maps`: `RegisterMap`, конфигурация транспорта, **две проекции единой карты** — бинарная Core v2 и managed Rx.
- `CoreLink.Client`: публичная точка приложения; загружает обе карты, владеет Core/Rx, буферами и lifecycle.
- `CoreLink.Rx`: синхронно запрашивает готовые snapshot **через Client**, выбирает обозначения единиц, публикует изменения и статусы. Не читает Modbus.
- `CoreLink.Adapter.CSharp`: реализация `ICore` над C# Core. Rust-адаптер/ядро — возможность на будущее, не существующий компонент.
- `CoreLink.Core`: декодирование карты и регистров, согласованный последний snapshot, статусы; не выполняет Rx/UI.
- `CoreLink.Transport`: Modbus TCP FC04, polling, request timeout, reconnect, диспетчер запросов; не декодирует managed Rx-карту.
- `CoreLink.Client.TestHost`: интеграционный стенд Client + Rx. `CoreLink.PlcSimulator`: отдельный инструмент испытаний.

Без reflection/scanning/DI-контейнера для выбора адаптера; реализацию `ICore` передаёт вызывающий код. Не переносить Modbus-адреса в Client, Rx или UI.

## 3. Текущий ICore и жизненный цикл

```csharp
public unsafe interface ICore
{
    CoreStatus Start(CoreMap coreMap);
    CoreStatus Stop();
    SnapshotStatus GetSnapshot(float* buffer, int length);
    event Action<CoreStatus>? StatusChanged;
}
```

`ICore` реализует адаптер. Client создаётся как `CoreLinkClient(IMapProvider, ICore)`, выполняет `Start(mapId)`, `GetSnapshot(out ReadOnlyMemory<float>)`, `StopAsync()`; публикует `Values` и `Statuses` через принадлежащий ему Rx. После `Stop` новый `Start` на том же экземпляре не поддержан.

Три разные сущности **не смешивать**: `CoreStatus` — состояние ядра; `SnapshotStatus` — результат конкретного чтения; `CoreLinkState` — lifecycle Client. Концептуальные View-статусы `Connected/Connecting/Disconnected/NoData/BadConfig/Error` не объявлять реализованным публичным enum без проверки API.

## 4. Два независимых цикла и память

```text
PLC → Transport polling → ushort[] → Core decode → internal snapshot
Rx → Client.ReadRxSnapshot → ICore.GetSnapshot → Client float[] → RxValue → HMI
```

- `PollIntervalMs` определяется картой; Rx-интервал `RxIntervalMs` задаётся **отдельно** (сейчас 500 мс). Client не создаёт третьего polling-таймера.
- `GetSnapshot` синхронно копирует **уже подготовленные** значения и не обращается к ПЛК.
- У Client два отдельных постоянных буфера `float[]`: публичный и предназначенный для Rx. Указатель `float*` действует лишь внутри `fixed`; Core его не сохраняет.
- Rx обрабатывает успешные snapshot последовательно и публикует `RxValue(ValueId, Name, Value, Unit)` при изменении числа **или обозначения**; для подписчиков не отдаётся изменяемый рабочий массив.
- До первого успеха — `NoData`; после потери связи — `Disconnected` без публикации устаревших значений как свежих. Последние значения хранятся, а не заменяются нулями.
- При Stop сначала завершается Rx, затем Core; конкурентные вызовы Stop используют одну задачу. Прочность этого пути проверялась симулятором.

## 5. Карта и Measurme

**Core binary v2 не меняется ради единиц.** Little Endian, заголовок 33 байта, `ValueCount` записей по 3 байта (`ushort Address` и `byte Type`); `CoreMap.BufferLength` — число значений, не байтов.

`RegisterMap` задаёт порядок `ValueId == index`, Modbus-адрес и тип. `Float32` из двух регистров занимает один ValueId. Managed Rx-карта включает `RxMapValue(Name, IReadOnlyDictionary<int,string> Units)`, `SupportedUnitSystemIds`, `UnitSystemValueId`, `RxIntervalMs`.

`Measurme` — **точное техническое имя**, не исправлять на `Measurement`. Текущая тестовая карта: 9 значений, `Measurme` — ValueId 8, физический адрес 0. Зарегистрированы системы 1 (UA), 2 (EU); новые положительные ID добавляются **в карту, не в алгоритм Rx**.

| Значение Measurme | Обозначение | Ошибка |
| --- | --- | --- |
| 0 | Пусто для всех параметров | Нет |
| Зарегистрированный положительный ID | Символ из карты; пусто, если у параметра символ отсутствует | Нет |
| Незарегистрированный ID / нецелое или недопустимое значение | `—` | Диагностика выбора системы |
| Регистра Measurme нет | Система 1 по умолчанию (должна быть зарегистрирована) | Нет |

При неизвестном ID сохраняется **число**, меняется только обозначение. Ошибку логировать при смене причины, не каждые 500 мс; при восстановлении — запись о восстановлении. `Trace` сейчас временный диагностический канал: его вывод/персистентность в TestHost **не подтверждены**. Полный контракт — [MAP_PROMT.md](MAP_PROMT.md).

## 6. Факты испытаний на 10.11.2026

Подтверждено пользователем:
- `dotnet build` из корня решения — успешная сборка восьми проектов под .NET 10 (10.11).
- В стабильном 60-секундном тесте после расширения Measurme: **121/121** завершённых Modbus-запросов, **120** `Snapshot Ok`, **0** ошибок snapshot, **488** событий Rx, `Stop Ok` и повторный `Stop Ok`.
- `Measurme` 0 → пустая единица; 1 → psi; 2 → bar/MPa; неизвестные 3/5/8/9 → `—`; возвращение к известной системе восстанавливает символы.
- При смене 9 → 8, пока оба ID неизвестны, Rx не перепубликует все значения исключительно из-за смены ID.
- В предыдущих испытаниях подтверждались reconnect после отключения PLC и восстановление после HANG с открытым TCP; не переносить эти результаты автоматически на каждый будущий вариант конфигурации.

**Не подтверждено:** полнота/однократность `Trace` в реальном журнале, успешный тест зарегистрированной третьей системы, производственный логгер, full NativeAOT publish и промышленная эксплуатация.

## 7. Не реализовано / не расширять самовольно

- Read/Write одиночных и блочных операций через `Client → ICore → Core → Transport` — требование, **не реализованное в текущем ICore**. Второй диспетчер запросов не создавать.
- Публичная агрегация статусов View и производственное централизованное журналирование — отдельные задачи, API не придумывать.
- Rust/FFI, OPC UA, новый бинарный формат карты, автоперезапуск Core после внутреннего Error — не часть текущей версии.
- Не менять уже протестированные механизмы Transport, timeout, reconnect, формат карты и API без отдельного основания.
